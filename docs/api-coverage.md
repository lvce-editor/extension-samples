# Extension API sample coverage

This inventory compares the published `@lvce-editor/api` entry points used by extension authors with the runnable browser playground samples. A sample demonstrates a user-facing capability; it does not need to repeat every type, registry snapshot, or low-level helper used to implement that capability.

| Notifications and dialogs      | `showNotification`, `confirm`                                                                     | [Hello World](../packages/sample-hello-world), [Dialog](../packages/sample-dialog)                                                                                                                                                                                                                                                                                                                                                |

The playground uses the tree-shakeable `@lvce-editor/api` package and its browser runtime. It does not use the legacy `extension-host-worker` facade as its sample import surface. The legacy facade contains host and registry plumbing beyond the author-facing browser package; those helpers are not separate sample requirements.

## Remaining capability inventory

Audited against the installed `@lvce-editor/api` 9.46.0 `dist/index.js`. The rows below are gaps, not claims that an exported API works in the browser playground. Runtime restrictions must be established per capability before excluding a sample.

| Capability / exports                                                                                                | Current coverage or next verification                                                                                                     |
| ------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| Brace completion, closing tags, comments, document symbols, implementations, references, selections, tab completion | No dedicated sample. Verify the corresponding language-provider path and add deterministic small-language examples.                       |
| Signature help (`registerSignatureHelpProvider`)                                                                    | No sample; needs a matching editor trigger and observable parameter help.                                                                 |
| Editor line and gutter decorations                                                                                  | No sample; verify provider dispatch, repaint and disposal in the preview.                                                                 |
| Editor selections, diagnostics, formatting, completions                                                             | Provider examples exist; direct `getEditorSelections` / `setEditorSelections` calls are not demonstrated yet.                             |
| Language servers (`registerLanguageServer`)                                                                         | No sample; choose a browser worker server before treating native process launch as required.                                              |
| Debug providers (`registerDebugProvider`)                                                                           | No sample; requires a runnable debug adapter and a debug session acceptance scenario.                                                     |
| File watching and file-change handlers                                                                              | No sample; verify changes are delivered to the preview application and watchers are disposed on reload.                                   |
| Workspace progress providers                                                                                        | No sample; verify the renderer consumes progress for the preview workspace.                                                               |
| Port providers (`registerPortProvider`)                                                                             | No sample; requires a meaningful forwarding endpoint.                                                                                     |
| Authentication providers and `getAccessToken`                                                                       | No sample; use a local test provider before deciding whether account infrastructure is necessary.                                         |
| Secret storage                                                                                                      | No sample; verify host storage isolation and delete any demonstration secret after use.                                                   |
| Cache storage and file handles                                                                                      | No sample; verify browser support and use isolated disposable keys.                                                                       |
| Themes, configuration definitions and settings navigation                                                           | No dedicated sample; verify settings UI ownership before adding one.                                                                      |
| Filesystem helpers (hashes, blobs, object URLs, directory mutations)                                                | File-system and text manipulation examples cover basic I/O; utility variants do not each require a separate sample.                       |
| Workspace switching / recent workspaces, tab focus and close, panel navigation                                      | Existing samples open files and panels; remaining navigation helpers can be grouped into a workspace example after isolation checks.      |
| Markdown virtual DOM and pretty errors                                                                              | Utility helpers can be incorporated into an existing view or error example.                                                               |
| Electron WebContentsView                                                                                            | Requires Electron; cannot run in the static browser preview.                                                                              |
| Node RPC (`createNodeRpc`)                                                                                          | Requires a Node endpoint; cannot run unchanged in a static browser preview.                                                               |
| Generic RPC / WebRTC audio                                                                                          | No sample; requires a connected peer, permission handling and stream cleanup.                                                             |
| `handleExtensionManagementMessagePort`, registry snapshots/resets, provider execution and view state registries     | Runtime/integration plumbing; ordinary extension examples exercise these indirectly through activation, contributions and view lifecycle. |

The legacy facade in `extension-host-worker` additionally exposes environment/process helpers, HTTP JSON requests, text offset/position helpers, workers, text search, web views and error classes. Native process and legacy host requirements must be documented if adding examples using that facade; the playground currently bundles the tree-shakeable API. The facade's registration methods overlap the public contribution capabilities above.

## Validation status

Status bar, output, rename, code action and preferences samples are candidates until their browser acceptance checks pass on published dependencies. Current investigation found application-context gaps in preferences, output-channel runtime discovery and status-bar provider dispatch, plus a renderer initialization defect when upgrading the playground runtime. Dependency fixes and their required cross-platform CI must land before these examples can be called runnable.
